## 六轮完整基线对照

顺序 ABC、BCA、CAB、CBA、ACB、BAC，A=Heavy CPU、B=RTMPose CPU、C=RTMPose CUDA。18 个独立进程全部成功；每进程 30 帧×3遍，每配置共 **540 次真实推理**。下表每帧数值为“各进程后两遍中位数，再跨六轮取中位数”；范围是六轮中位数的最小～最大，**不是置信区间**。

| 配置 | 热遍每帧中位数（轮间范围） | 本批端到端中位数 | 进程树 RSS 峰值范围 |
|---|---:|---:|---:|
| Heavy CPU | 40.96 ms（38.10～44.86） | 6.380 s | 337.2～337.5 MiB |
| RTMPose CPU | 149.22 ms（147.64～152.67） | 15.276 s | 359.9～372.5 MiB |
| RTMPose CUDA | 47.53 ms（45.70～49.23） | 7.120 s | 1295.7～1408.1 MiB |

本批端到端=共同源素材准备 0.640970 秒+每个三遍进程全程（导入、加载、PNG读取、检测、姿态、选择、角度、JSON与退出采样），排除空闲门禁等待、模型下载、Tauri UI/Rust。原始进程全程中位数为 5.739 / 14.635 / 6.479 秒。不能把本批三遍总时间当一次视频分析时间，也不能拿热遍每帧数代替冷启动响应。

CUDA 第三轮首遍均值 **373.5 ms/帧**，该进程全程 **15.360 s**；其他轮首遍约 76.2～103.8 ms/帧。这段首遍长尾完整保留，原因尚未通过 kernel profiler 归因，不能只报告热遍而声称冷启动稳定。模型载入约 0.57～0.59 秒，并不包括所有首次执行开销。

Windows WDDM 进程显存查询为 N/A，模型进程显存为 **null**。整卡显存含其他应用，未将其代替模型显存。RSS为工作进程树采样合计，共享页可能重复计算。

## 阶段诊断与传输对照

默认 CUDA 管线的跨轮阶段中位数：PNG 读取解码 7.48 ms，人体检测总计 25.21 ms（其中含传输执行 24.12 ms），姿态总计 14.38 ms（其中含传输执行 11.36 ms）。每帧姿态调用数中位数为 **3 人**，不是每帧只推理一个人；人体检测后没有因为人工框而跳过其他人。Heavy公开接口内部检测+姿态合计约 32.69 ms，无法诚实地再拆其内部子阶段。

另外对同一批 30 帧做标准 CUDA 与 IOBinding 诊断的 **4 轮交替**，共 8 个成功独立进程、每模式360次推理。标准模式热遍中位数 48.02 ms，显式绑定模式 47.01 ms。绑定模式分项：

| 阶段 | 检测器 | 本帧所有人的姿态推理合计 |
|---|---:|---:|
| 输入分配/复制/绑定/同步 | 0.387 ms | 0.328 ms |
| 执行并同步输出 | 23.152 ms | 10.763 ms |
| 输出复制到 CPU | 0.047 ms | 0.222 ms |

各项分别取中位数，不要求和总体中位数严格相加。计时为主机墙钟，执行段可能包含 CPU 节点与输出分配，不是 GPU kernel 时间。显式输入/输出传输开销在本诊断中小于执行段，不能据此泛化所有平台或否认内部额外复制。依据这些结果推断，先前 GPU 高负载是候选较慢的一个可能因素；新旧测量环境、输入子集和统计口径不完全相同，未把差异全部归因于单一原因。

两模式等价检查在同一 30 帧上比较全部 **79 个人体检测实例**的映射点，最大坐标差 **0 像素**、最大分数差 **0**，预先固定容差为0.01像素/0.00001。这里只验证执行模式没有改变这批预测，不能称为准确率。

本片段上候选 CUDA 虽比候选 CPU 快，仍未显示超越 Heavy 的管线速度收益，内存占用更高。缺少人工误差与覆盖证据，继续保留 Heavy，不进入产品接入或 RTMW 扩展。

## 证据与复核

`baseline/` 和 `transfer/` 分别包含冻结数据、run、timing-summary、provenance以及 `raw-predictions.zip`。归档只有完整预测 JSON 和门禁 JSON，不包含图片、视频、权重、虚拟环境或密钥。每个归档成员的长度/SHA-256与归档本身的SHA-256都在provenance中；Git不转换证据JSON换行。

已实际重新读取26组原始预测并重算阶段汇总，与保存的timing-summary完全一致；数据哈希、每组90行、门禁通过、归档CRC和全部成员SHA-256均核验通过。`provenance.source_files` 记录本机执行脚本的字节哈希（另一个Git检出环境的源码换行转换可能改变这个哈希，证据JSON本身不转换）。原始stdout/stderr与逐帧PNG仍在本机 `experiments/local/controlled-pilot-final`、`transfer-pilot-final` 和 `annotation-pilot`。

复核时先验证归档哈希，再解压到单独临时目录（不要覆盖当前实验结果），将对应run.json与dataset.json放在根部。`benchmark.summarize(run['runs'], 解压目录)` 应等于timing-summary；`evaluate.py` 可在冻结数据上重算误差状态。PNG可由同一仓库视频按 [清单](../annotation-pilot-manifest.json) 重新准备，逐帧SHA-256应一致，准备墙钟时间及其记录文件哈希会随新运行变化。

标注操作见 [人工标注说明](../annotation-guide.md)，运行协议见 [模型对照](../model-comparison.md)。

# ShotForm 存量界面独立视觉审计

日期：2026-11-15。方法：按 `oil-ui/references/reviewer-manual.md` 的“存量已有界面润色评审”执行，只对齐 `DESIGN.md`，不打分。仅阅读规范、指定截图及原始 `evidence-upload/report.json`，未读源码、未修改业务实现、未操作产品。

证据已复核：制作方在等待 networkidle、字体与图片解码及双 rAF 后重取了截图，本报告以重新读取的稳定单图为准。早期“深色空分析页标题和正文黑字不可读”的观察已撤销；稳定画面标题和正文为白色。早期侧栏“首页高亮”的观察也撤销，稳定画面在分析和比较页没有明显当前项。首页三张功能卡标题低对比仍成立。

## 速查清单

- [问题 1 / P1] 深色文字与按钮：首页功能标题和部分控件对比不足 → 深浅主题正文至少 4.5:1、大字至少 3:1，空态与主动作可直接读清。
- [问题 2 / P1] 状态和错误表达：技术异常、空态与加载失败混在一起，局部标识容易误导 → 用用户能执行的下一步解释当前状态，既不把失败显示成空记录，也不暗示所有处理都在本地。
- [问题 3 / P2] 内页层级：重复面板、横幅与装饰争夺工作空间 → 结论、当前对象及主动作构成一条清晰阅读路径，减少同一任务的重复容器和入口。
- [问题 4 / P2] 控件语义与一致性：普通操作、选中态和证据混用铜色，按钮尺寸及表面不统一 → 普通交互遵循 Steel Blue/中性色，证据强调保留 Shot Copper，同类控件外观与状态一致。
- [问题 5 / P2] 窄窗和放大：固定侧栏与页头挤占工作区 → 960×640 和 200% 放大下，当前任务、输入与主动作可达，正文不裁切、操作不重叠。

## 具体问题与验收

### 1. P1：深色主题的关键文字失去可读性

**依据：** `baseline/dark-home.png` 底部“精准识别 / 节奏分析 / 可视化报告”标题几乎融入卡片。`baseline/zoom200-upload.png` 选中的“视频分析”使用深色文字配中等亮度蓝底，与旁边白字标签不一致；`baseline/dark-analysis-empty.png` 的横向主按钮也使用黑色文字配蓝底，应按实测对比值验收，不能仅凭黑字判定不合格。稳定后的空态标题和正文是白色且可读。`baseline/light-upload.png` 的格式、大小、时长提示颜色偏浅。

**规范与影响：** 首页功能标题偏离 Text Strong Light / Text Soft Light 的主题角色；部分蓝底按钮与白字按钮关系不一致，需要实测后统一。用户无法快速读清首页功能说明，弱提示与动作状态也容易被忽略。

**验收：** 在深浅主题重新测量实际文字与实际背景，不只检查 token 值；正文与标签至少 4.5:1，大字至少 3:1。截图中空态标题、说明、主动作及首页三项标题都应无需放大即可识别。禁用态另按真实语义检查，不能通过将关键状态标成“禁用”回避修复。

### 2. P1：错误、空态与信息边界表达需要统一

**依据：** 稳定单图 `baseline/dark-history.png` 显示 `TypeError: Cannot read properties of undefined (reading 'invoke')`，下方同时显示“还没有投篮档案记录”；`baseline/dark-templates.png` 同样暴露技术错误；`baseline/dark-compare-error.png` 出现三处 `Preview template load failed.`。这些可能来自预览环境，但用户可见呈现仍将技术错误与空数据混淆。`dark-analysis-empty.png` 与 `narrow-compare.png` 的侧栏无明显当前工作流选择态。`dark-home.png` 与 `light-home.png` 的隐私说明写明 AI 分析会发送图像和数据至云服务，而旁边独立绿色徽标仅写“本地处理”，扫描阅读时容易产生全流程本地的印象。

**验收：** 无数据、请求失败、环境能力不支持三类状态有明确区分；失败画面包含合适的恢复入口，技术细节收纳于按需查看内容，不在多个模块反复输出同一异常。当前工作流归属与页标题一致。主页本地处理标识准确限定范围，并保持现有云端处理披露。不得通过删除真实错误和披露来制造正常状态；不得将当前预览异常推断为桌面端业务失败。

### 3. P2：工作台的结构层级被重复外壳和页头装饰削弱

**依据：** `narrow-compare.png` 在页头提供“管理球星模板”，紧邻的内部工具栏再次提供“管理模板”；外层大圆角面板内包工具栏圆角面板，再包模板卡和图表卡。960×640 首屏主要用于标题、说明和模板介绍，差异图表只露出标题。`light-history-editor.png` 形成“分组容器—记录容器—编辑容器—字段”的多层边框，训练备注编辑区域占据主要可视高度；背景人物仍在过滤器后方。`dark-analysis-fixture.png` 中结论、人物图和右侧模块并排，左侧为配合人物图留出大段空白，角度分析从屏幕底部才开始。`light-upload.png` 内页仍保留宽大运动员背景和较高的介绍区。

**规范与影响：** 偏离“工作台使用更宽、更平静的表面”“同一任务先合并视觉分组”“结论优先、证据其次、细节最后”。问题不是侧栏或分栏本身，而是重复结构没有增加业务关系，证据与下一动作被挤远。

空分析状态也需纳入结构统一：`dark-analysis-empty.png` 把小标题、说明和横跨几乎整个工作区的上传按钮贴近顶部，余下大面积空白；虽文字可读，仍缺少与其他页一致的页面层级和有节制的动作尺寸。

**验收：** 合并同任务的重复外壳和模板管理入口，训练日期、标签、备注、保存/取消、恢复、对比及导出仍完整保留。1440×900 的分析首屏能迅速定位判断及支撑它的关键证据；比较首屏清楚展示所选对象与比较重点；历史页能扫读记录并识别编辑归属。背景图不穿过工作区形成额外视觉焦点。所有删减以强化既有任务为准，不添加数据或功能填空。

### 4. P2：交互色与证据色的职责发生混用

**依据：** `light-upload.png` “选择视频”为高饱和橙色渐变；`dark-analysis-fixture.png` HTML 导出和图表切换均使用铜色填充；各页侧栏当前项也使用铜色。上传模式按钮、历史页“筛选/重置”和记录行操作呈紧贴文字的窄按钮，训练对比“导出对比报告”又采用另一种蓝色表面。`narrow-compare.png` 普通工具按钮呈较大的胶囊形，与工作台其他控件不一致。

**规范与影响：** DESIGN 明确 Steel Blue 用于交互、Shot Copper 用于关键证据或选中解释；普通上传和导出不应共同消耗证据强调。Buttons 规定工作台为中等圆角，并要求同类主/次/弱操作有稳定关系。截图可判断外观不一致，但不能据此断言某控件未复用组件，也不能仅凭像素图确认全部颜色十六进制值或字体加载情况。

**验收：** 普通 CTA 和选中控件按规范分配 Steel Blue 或中性色；铜色聚焦于有证据意义的内容。同类按钮采用一致的高度、内边距、圆角、文字对齐和状态关系，中文标签不贴边。深浅主题各截取上传、筛选、保存、导出、模板工具栏，横向核对可读性与主次；hover/focus/pressed 另做交互验证。

补充静态证据：稳定后的 `dark-delete-dialog.png` 中标题与说明几乎贴在对话框左边缘，“删除”按钮紧贴右边缘，属于同一类内边距不一致。保留其明确的不可恢复说明与危险色，统一内容和动作区域的安全边距。主 Agent 另行反馈已验证取消为初始焦点、Escape 关闭且未删除数据；这不是本独立评审的亲自操作结果。

### 5. P2：放大和窄窗时，结构未充分让位于任务

**依据：** `zoom200-upload.png` 中侧栏宽约 420px，占 1440px 画面约三成；正文从约 x=476 开始，眉标、大标题、说明、模式切换和环境提示持续堆叠，上传区域仅露出图标，“选择视频”未进入首屏。`narrow-compare.png` 960px 画布仍保留约 210px 侧栏，模板文字与两列结构占据大部分可用宽度和高度。当前截图未证明横向溢出或主动作不可滚动到达，因此不将其误报为已证实阻断。

**验收：** 在这两种尺寸下检查完整页面和键盘遍历：所有文字、表单、按钮、对比数据和窗口操作均可达，没有裁切、遮挡或双重滚动陷阱。压缩重复页头与装饰空间，使核心操作能尽早出现；必要时调整导航及模块布局，保持所有路由和功能可达。200% 证据来自 CSS zoom=2，还需另验真实浏览器缩放和系统文字缩放。

## 可直接删减或合并的文案与装饰

- 内页 `UPLOAD / ANALYSIS / HISTORY / COMPARISON` 眉标重复中文标题，不承载任务状态，可删除；原始 lint 的 UPLOAD 提示没有记录任何保留理由。
- Compare 的“管理球星模板”和“管理模板”保留一个稳定入口即可；模板卡上的球星名称如已由标题给出，无额外语义的同名胶囊可去掉。
- 首页英文品类胶囊、底部三张功能介绍卡与虚线圆环均可减弱或删减，给“投篮瞬间 + 一个开始入口”腾出视觉空间；保留必要隐私说明，其准确性比画面稀疏更优先。
- 内页“基于动作识别和关键帧分析，为你提供专业的投篮姿势评估”等重复产品介绍可缩短，当前对象、结果和下一动作无需再由广告式引言解释。
- 不删除格式/大小/时长限制、浏览器能力提示、置信度限制、训练对比“变化值不代表进步评分”、云端处理披露或真实错误状态。Fixture 的“UI 审计夹具，不代表实测结果”属于审计证据保护，不是当前产品多余文案，不应从证据截图中抹去。

## 默认做法提示的原样读取与处置判断

`evidence-upload/report.json` 对 page.png 与 page-@2x.png 均记录 `eyebrow` 1 项，例为 `p.upload-page__eyebrow「UPLOAD」`；均记录 `contrastLow` 10 项，例为 `span.app-sidebar__logo-sub「投篮分析大师」（2.66:1）`、`span「首页」（4.22:1）`、`span「上传视频」（2.46:1）`。这些是原始记录，不等于本次另测得的数据；截图中能确认相关文字偏弱。眉标建议删，低对比逐项复测并修复，不默认为已有保留理由。原记录 `issues: []` 不能视为界面无问题。

动效探针记录“首次进入：没有检测到动画”，同时记录因未安装 ffmpeg 仅留三帧、`failed: true`。本轮仅审静态截图，没有看到动效，不能据此确认所有动画缺失，也不能声称雾化过渡、hover、tab 反馈或 reduced-motion 已通过。

## 提升方向与证据边界

- **精致度：** 在现有品牌、字体和色板内，优先统一按钮内边距、边框力度、文字主题映射与主内容锚线。不能从截图确认真实字体文件、8px 间距体系和精确 token，需要实现方另验。
- **设计感：** `dark-home.png`、`light-home.png` 的完整球员投篮动作与“出手节奏”已有明确篮球关联；保持此主角，减少底部组件堆叠，使首页更接近规范中的电影封面。旧 overview 首页图未加载完成，未将缺图作为缺陷。
- **动效：** 未验证；后续以正常速度录屏检查主页入场、封面至工作台雾化过渡、操作状态反馈及 reduced-motion。不得为工作台增加持续装饰动画。

未验证：上传选择/拖拽、视频裁剪、分析计算、模板加载、保存恢复、标签和备注持久化、删除确认、两次训练比较、HTML/JSON/对比报告导出、导航点击、键盘及屏幕阅读器、真实应用窗口缩放和所有动效。Fixture、history-editor、training-comparison 为合成数据，Compare 为项目既有预览；本审计不判断算法准确性、置信度真实性或训练效果，也未调用任何付费 AI。

保留：深浅主题共享中性色与篮球铜色的品牌基础；首页完整投篮动作和单一开始入口；训练对比清楚区分前后记录、变化值、不可比较原因，并明确“变化值不代表进步评分”的可信表达。

本报告不打分，修改目标是遵循既有 DESIGN.md，不建议更换整体品牌色或字体。
